# OPC (One Person Company) 可视化管理工作台高级产品需求文档 (PRD)

## 1. 产品定位与愿景

OPC 可视化管理工作台（OPC Dashboard）是整个“一人公司”操作系统的中枢神经。它不仅仅是一个任务管理工具，而是一个**多智能体公司的全景指挥中心**。

它的核心愿景是：**让 CEO（人类）能够像玩模拟经营游戏一样，以上帝视角管理由 20 个 AI Agent 组成的虚拟公司，实现从线索获取、销售转化、生产交付到财务结算的商业闭环全流程可视化与可控化。**

## 2. 核心设计理念

1. **上帝视角与逐层折叠**：首页展示公司级核心指标（收入、线索、交付率），点击可逐层下钻至具体团队（营销/生产/运营）、具体 Agent，直至具体的单次对话或文件修改记录。
2. **状态机驱动的可视化**：将底层的 `STATUS_MACHINE.json` 转化为直观的看板（Kanban）或甘特图（Gantt），让工作流的流转一目了然。
3. **“人机共生”的交互模式**：提供全局命令行（CLI）和实时对话窗口，CEO 可以随时介入任何一个 Agent 的工作流，进行指导、审批或接管。
4. **高度自定义与扩展性**：支持自定义工作流、自定义 Agent 技能、自定义 API 密钥切换，满足公司业务扩展的需求。

## 3. 核心功能模块 (8 大模块)

### 3.1 组织架构与角色管理 (Org Chart & Agents)
- **可视化组织架构图**：展示公司层（小探、小播、小销、小服）与生产层（龙虾军团：设计团队、开发团队）的层级关系。
- **Agent 角色卡片**：点击任意 Agent，展示其详细信息（头像、职责、当前状态、正在执行的任务、历史产出）。
- **自定义 Agent**：支持通过可视化表单创建新 Agent，定义其 Prompt、接入的 API 和所属团队。

### 3.2 全流程业务看板 (Workflow Kanban)
- **全局状态看板**：基于 `STATUS_MACHINE.json`，展示所有活跃项目在 12 个状态节点中的分布。
- **跨团队流转追踪**：清晰展示项目在营销、设计、开发、交付团队之间的流转轨迹。
- **硬停触发器管理**：高亮显示需要 CEO 审批的节点（如：CEO 申请启动、大方向确认），支持一键审批。

### 3.3 工作成果与资产管理 (Asset Manager)
- **交付物橱窗**：集中展示所有已完成项目的最终交付物（代码、设计图、文案）。
- **知识库沉淀**：自动归档 KO（知识沉淀 Agent）生成的 `SKILL.md` 和复盘报告，形成公司的数字资产。
- **设计资产库**：可视化管理设计团队产出的 Design Tokens、Logo、插画等品牌资产。

### 3.4 实时对话与干预中心 (Intervention Center)
- **全局通讯录**：类似 Slack 的界面，CEO 可以与任意单个 Agent 或整个团队（如 `@design_team`）进行实时对话。
- **上下文注入**：对话时，系统自动附带当前项目的上下文（Brief、状态、最新产出），确保沟通高效。
- **强制接管**：在 Agent 遇到错误或偏离方向时，CEO 可以暂停其工作，手动修改文件或重置状态。

### 3.5 自定义规则与工作流引擎 (Workflow Builder)
- **拖拽式工作流编排**：类似 Dify 或 Flowise，通过连线方式定义 Agent 之间的交接规则和触发条件。
- **数据契约配置**：可视化编辑 `BRIEF_SCHEMA.json` 和 `DESIGN_HANDOFF_SPEC.md`，定义节点间传递的数据格式。

### 3.6 财务与运营大盘 (Finance & Ops Dashboard)
- **收入追踪**：对接 Stripe API，实时展示 MRR（月经常性收入）、ARR、客单价等商业指标。
- **成本监控**：按 Agent 或按项目统计 LLM API 的消耗成本，计算单项目利润率。
- **线索转化漏斗**：展示小探抓取的线索数 -> 小销发送的邮件数 -> 最终成交的转化率。

### 3.7 全局设置与 API 管理 (Settings & API)
- **API 密钥保险箱**：集中管理 OpenAI、Anthropic、Stripe、Twitter 等第三方服务的 API Key，支持一键切换模型。
- **系统级参数配置**：设置全局超时时间、重试次数、日志保留周期等。

### 3.8 命令行终端 (Integrated CLI)
- **内置终端**：为高级用户（CEO）提供直接执行 `opc-cli` 命令的入口。
- **快捷指令补全**：输入 `/` 触发常用管理命令（如 `/deploy`、`/audit`）。

## 4. 技术架构建议

- **前端框架**：Next.js (React) + Tailwind CSS + Framer Motion（用于流畅的动画过渡）。
- **UI 组件库**：shadcn/ui 或 Radix UI，打造极简、专业的极客风格界面。
- **状态管理**：Zustand 或 Redux，处理复杂的跨组件状态同步。
- **图表与可视化**：Recharts（数据图表） + React Flow（工作流编排与组织架构图）。
- **后端服务**：Node.js (Express/NestJS) 或 Python (FastAPI)，作为前端与底层文件系统/Agent 引擎的桥梁。
- **实时通信**：WebSocket (Socket.io)，实现 Agent 状态的实时推送和对话功能。

## 5. 交互与视觉规范

- **视觉风格**：深色模式（Dark Mode）为主，辅以高对比度的点缀色（如荧光绿、电光蓝），体现 AI 科技感与专业性。
- **一致性**：确保所有卡片、按钮、弹窗的圆角、阴影、交互反馈保持高度一致。
- **逐层折叠**：复杂数据（如长篇的 Prompt 或 JSON 配置）默认折叠，提供“展开查看更多”选项，保持界面清爽。

## 6. 开发路线图 (Roadmap)

- **Phase 1: 核心骨架与数据接入 (MVP)**
  - 搭建 Next.js 前端框架。
  - 实现读取底层文件系统（`status.json`、`openclaw.json`）的后端接口。
  - 完成“组织架构”和“全流程业务看板”的只读展示。
- **Phase 2: 交互与干预能力**
  - 实现“实时对话与干预中心”，打通前端与 Agent 的通信链路。
  - 支持在看板上直接修改项目状态（触发状态机流转）。
- **Phase 3: 资产与财务管理**
  - 开发“工作成果与资产管理”模块，支持文件预览与下载。
  - 接入 Stripe API，完成“财务与运营大盘”。
- **Phase 4: 高级自定义与扩展**
  - 引入 React Flow，实现“自定义规则与工作流引擎”。
  - 完善“全局设置与 API 管理”和“内置命令行终端”。
